# ADR-0001：技术选型与架构基线

- **状态**：已接受
- **日期**：2026-10-08
- **决策人**：项目所有者（经多轮方案评审确认）
- **关联**：`../arkreunion-design.md`（总设计）

本 ADR 记录 arkreunion 立项阶段的全部关键决策。每条含：背景 → 决策 → 备选与否决理由 → 后果。

---

## D1 开发语言：Rust

**背景**：要求跨平台（Linux/Windows/macOS）、单文件分发、低资源占用、可被包管理器引入（`cargo install`）；候选 Rust / Go / Ruby。

**决策**：Rust（axum + tokio + bollard + serde + rusqlite + tracing）。

**备选与否决**：
- Go：迭代更快、goroutine 适配调度，但二进制更大、生态精致度稍逊；用户在 Rust/Go 间倾向 Rust（长维护性）。
- Ruby（Sinatra/Hanami）：开发轻快，但 Windows 原生分发需打包运行时，跨平台承诺最弱。

**后果**：✅ 三平台单二进制（~10-15MB）零运行时依赖，内存占用极低，类型系统护航调度器并发。⚠️ 迭代速度慢于脚本语言 → 以文档先行 + AI 协作规范（AGENTS.md）+ golden 测试弥补。

## D2 前端：Vue3 + Vite（嵌入二进制）

**背景**：控制台为数据密集管理后台；要求可嵌入单二进制、可响应式覆盖手机；候选 Vue3 / React / Svelte / SolidJS / React Native / Flutter。

**决策**：Vue3 + Vite + Naive UI + ECharts + Pinia；构建产物 rust-embed 嵌入；PWA 适配手机浏览器。

**备选与否决**：
- React+Vite：生态最大（antd），但与 mower 自带 UI（Vue）栈不一致，RN 复用收益本期不成立。
- Svelte 5 / SolidJS：运行时最轻，但表格/图表/排程组件生态薄、中文资料少。
- RN/Flutter：手机原生体验佳但无法嵌入二进制、发布链路重 → 仅列为未来「手机伴侣 App」候选（复用本项目 REST/WS API）。

**后果**：✅ 与 mower 前端同栈，心智一致；组件库成熟。⚠️ 大型交互生态略逊 React——本项目后台场景够用。

## D3 账号切换：100% 调用 MAA 官方能力（硬性不变量 INV-1）

**背景**：单设备多账号的核心机制。候选：a) MAA「开始唤醒」`account_name`；b) 自研登录界面自动化；c) 每账号独立 app 数据目录切换。

**决策**：只用 a）。唯一实现路径 `switch::run_switch()` → `maa run startup -p default --batch`；禁止任何自研登录 UI 自动化；MAA 不可用即失败告警不降级。账号首次在某设备使用走人工预置（provision，一次性）。

**备选与否决**：
- 自研登录自动化：登录界面改版频繁，必然腐化；上游 MAA 资源持续维护，重造轮子无收益。（用户明确指示"务必调用 maa 提供的功能，不要造轮子"）
- 每账号独立数据目录（refill-akdata 式）：隔离彻底但切换慢（2-3min）、每账号数 GB 存储；留作未来可选模式，不进一期。

**后果**：✅ 维护成本转嫁给 MAA 上游；切号快（~1-2min）。⚠️ 依赖 MAA 资源跟进登录界面改版；新设备/新账号需一次性人工登录。

## D4 mower 多账号形态：每账号配置 bundle + 时间片会话

**背景**：mower 上游无游戏内切号（issue #340 官方建议即多实例）；mower 大部分时间挂机等心情。

**决策**：每账号一份 bundle（`accounts/<key>/mower/`），arkreunion 按时间片起停会话轮转；不常驻多实例。

**后果**：✅ 单设备即可多账号，资源最省。⚠️ 单账号日可用时长被摊薄 → M3 用空闲信号交叉调度找回效率。

## D5 mower 会话运行形态：DockerRunner + ProcessRunner 双 Runner

**背景**（评审发现的缺口）：原方案仅提"镜像重建"，无法满足跨平台无 Docker 场景（Windows 原生跑 mower）。

**决策**：Runner 子层抽象：DockerRunner（bollard，Linux/Docker Desktop；挂载 bundle 读写）与 ProcessRunner（本地检出 + `MOWER_DATA_DIR` 指向账号数据目录）。M1 双双交付，DockerRunner 先行（贴合现有验证环境）。

**后果**：✅ 跨平台承诺成立；bundle 直接读写挂载/符号链接 → 用户在 mower UI 的改动天然持久化（免除回拷同步）。⚠️ 两条运行路径都要测试覆盖。

## D6 设备抽象：DeviceBackend trait，一期 External、二期 RedroidDocker

**背景**：一期验证环境是已存在的 redroid 容器；二期要按需扩池；同时要支持 Windows 原生模拟器（MuMu/雷电）。

**决策**：`external`（只连不管，双地址 `host_adb`/`docker_adb`）与 `redroid`（bollard 全生命周期 + 水位准入，仅 Linux）两后端；并发上限由水位动态决定（用户选择），无人为硬上限。

**后果**：✅ Windows 用户 M1 即可用（External+ProcessRunner）。⚠️ Redroid 依赖 GPU/binderfs → 仅 Linux，文档明示。

## D7 CLI 与守护进程：daemon/standalone 双模式 + 工作目录文件锁

**背景**（评审缺口）：CLI 写操作与 daemon 调度器可能并发冲突。

**决策**：daemon（`arkreunion server`）单写者；daemon 存活时 CLI 一律走本地 API；无 daemon 时 CLI 直调库但必须先获 `state/.workdir.lock`（flock/LockFile）排他锁。daemon 运行期间的任何非 API 写路径视为 bug（CI 集成测试守护）。

**后果**：✅ 语义清晰无双写。⚠️ CLI 需实现 API 客户端回退逻辑。

## D8 配置与状态：文件树为事实源 + SQLite 运行态；zip 导入导出

**背景**：要求配置/日志/统计可迁移；Rust 单二进制。

**决策**：账号/设备/策略 = TOML/YAML 文件树（单一事实源，INV-4）；会话/事件/统计/端口/亲和 = SQLite（WAL，版本化 schema）。`arkreunion export/import` = zip{配置树 + arkreunion.db + manifest(schema_version)}，`--redact-secrets` 按字段名清单脱敏；高版本导入拒绝并提示升级。

**后果**：✅ 迁移路径确定；secret 策略显式。⚠️ 双源一致性需 INV-4 纪律约束。

## D9 项目形态：独立仓库式项目（本目录），rails 式 CLI

**背景**：用户要求独立项目、可安装（cargo install / Releases）、独立命令、可指定工作目录与 MAA/mower 目录。

**决策**：Rust workspace（`arkreunion-core` 库 + `arkreunion` CLI）；clap 子命令族（init/server/status/account/device/switch/session/maa/mower/export/import/doctor...）；全局 `--workdir`（cwd 向上探测 arkreunion.toml）+ `--maa-dir/--mower-dir` 覆盖。目前暂驻 `/srv/arknights/arkreunion/`，结构按独立仓库组织，后续可整体迁出。

**后果**：✅ 分发与二次开发（引 arkreunion-core 库）两全。⚠️ 迁出独立仓库时需保持历史（git subtree/filter）。

## D10 调度一期范围：单模拟器静态时间窗（裁剪）

**背景**：避免一期摊子过大。

**决策**：M1 = 单 External 设备 + 串行会话 + 静态时间窗/优先级/时间片 + 看门狗/退避/双超时；多设备水位扩容（M2）与事件驱动交叉调度（mower 空闲信号换号、跑单窗口锁定，加分项）分期。失败退避吸取 mower「加工站空扫死锁」issue 教训（失败任务必须指数退避，不得短周期空转重试）。

**后果**：✅ M1 可在现有部署上完整验证。⚠️ 跨账号效率优化延后。

## D11 文档基础设施：三受众分层

**决策**：`docs/ai/`（AGENTS.md + ADR）、`docs/dev/`（开发/API/测试）、`docs/user/`（部署/配置/FAQ）；设计文档 `arkreunion-design.md` 为唯一权威总设计，行为变更须先改文档。

**后果**：✅ AI 协作、人类开发、最终用户各有入口；文档漂移有制度约束。
