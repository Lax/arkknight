# ADR-0002：mower conf.yml 白名单改写采用 serde_yaml 语义级 patch

- **状态**：已接受
- **日期**：2026-10-08
- **关联**：`../arkknight-design.md` §11.3/§11.4（物化器与双向规则）、`crates/arkknight-core/src/materialize/mower.rs`

## 背景

设计文档 §11.3 要求 mower 会话启动瞬间对 `conf.yml` 做「serde_yaml 精确 patch，
不整文件重写」，以保护用户（含 mower UI）对 bundle 的其他改动（§11.4 双向规则）。
实现时发现 Rust 生态没有成熟的**注释/键序保真** YAML 编辑库（serde_yaml 已归档，
yaml-rust2 系列的往返同样不保留注释），完全保真的文本级 patch 复杂度不成比例。

## 决策

1. **语义级白名单改写**：解析整个 YAML → 仅插入/覆盖 4 个键
   （`adb`、`start_automatically`、`webview.port`、`webview.token`）→ 反序列化回文本。
   其余键的**值**一律原样保留；文件注释与键序不保真（会被标准化）。
2. 改写**仅在会话启动瞬间**执行（时序约束不变，§11.4）；会话运行期间与结束前
   不再覆盖，用户在 mower UI 对这 4 个键的修改以用户为准。
3. golden 快照锁定 4 键改写行为与「其余键保留」语义（`tests/golden/mower_conf_*.yaml`）。

## 后果

- ✅ 双向规则的本质（用户配置值不被覆盖）成立；实现简单、幂等、有快照护航。
- ⚠️ 用户在 `conf.yml` 中的注释会丢失。缓解：mower UI 编辑本身也不保注释，
  实际损失面小；若未来需要，换 patch 式编辑器并保持 `patch_conf()` API 不变。
- 设计文档 §11.3 的「不整文件重写」按本 ADR 解释为「不改写白名单之外的语义」。
