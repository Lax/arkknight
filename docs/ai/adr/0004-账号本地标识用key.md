# ADR-0004：账号本地标识用 `key` 而非 `id`/`slot`/`profile`

- **状态**：已接受
- **日期**：2026-10-09
- **关联**：`../arkknight-design.md` §6.1、§14（BREAKING 变更）

## 背景

`Account` 有四个与「账号是谁」相关的字段，语义各不相干：

- `display_name`：仅供展示
- `account_name`：**游戏侧**标识 —— MAA 切号匹配串（官服=打码手机号片段，B服=昵称）
- `uid`：**游戏侧**标识 —— 游戏 UID，切号后 OCR 核验身份
- 第四个字段原名 `id`：**本项目内部**概念 —— 工作目录名 `accounts/<id>/` + CLI 位置参数

问题：四个字段里三个与游戏身份相关，唯独 `id` 是纯内部概念，却用了最容易与
「游戏账号 ID」混淆的名字。控制台新建账号表单里 `id` / `account_name` / `uid`
三个输入框并列时，用户难以判断哪个该填游戏账号、哪个填内部标识。

设计文档 §9.4 记录的真实故障（MAA 匹配串太泛时**静默登进错误账号**，MAA 退出码仍是 0，
arkknight 无从察觉，随后在别人号上跑基建）加剧了这种混淆 —— 那次故障的根因
就是「切号匹配串」这一层被误解了。

## 决策

`Account.id` → `Account.key`，并在模型 doc comment 与设计文档 §6.1 显式写出四字段分工：

| 字段 | 归属 | 含义 |
|---|---|---|
| `key` | 内部 | 本地定位键（目录名 + CLI 参数） |
| `display_name` | 内部 | 展示名 |
| `account_name` | 游戏侧 | MAA 切号匹配串 |
| `uid` | 游戏侧 | 游戏 UID，核验身份 |

同时在 UI 表单把三者分到不同分组、每字段下加一行说明其用途。

## 备选与否决理由

- **`slot`**：语义贴切（多账号按时间片轮转，账号就是设备上的一个轮转槽位），
  且与游戏身份区分最彻底。**否决**：`scheduler::ActiveSlot`（当前活跃会话槽）
  已占用该词，同一代码库出现两种 slot 指不同事物，读 `handle.active: ActiveSlot`
  与 `account.slot` 会混淆。
- **`profile`**：**否决** —— MAA 的 `profiles/default.toml` 与 `maa run -p <profile>`
  已把该词用作「MAA 连接配置」。让 `accounts/<key>/maa/profiles/` 这类路径同时
  含「账号 profile」与「MAA profile」两义，含混。
- **`name`**（与 `Device.name` 对齐）：两个模型命名统一。**否决**：
  `Account.name` 与 `Account.display_name` 极易混淆 —— 一个是定位键一个是展示名，
  仅靠文档区分太弱。保持「键」与「名」的字面区分度更重要。
- 保持 `id`：**否决** —— 见背景，混淆风险已在 UI 上实际发生。

## 后果

✅ 四字段语义清晰，UI 与 CLI 都消除了「哪个是游戏账号」的歧义；
`key` 在项目内未被占用（store 的 `key` 仅指 `meta` 表主键，语义无关）。

⚠️ **BREAKING**：
- `account.toml` 字段 `id` → `key`。用 `#[serde(alias = "id")]` 兼容旧文件读取，
  落盘一律写 `key`。
- SQLite 四张表（sessions/switch_log/logins/stats_daily）的列 `account_id` →
  `account_key`，schema v1 → v2，迁移用 `ALTER TABLE … RENAME COLUMN`。
  `SCHEMA_V1` 保持原样不改，新库直接建 v1 再靠迁移到 v2，保证「建表」与「迁移」
  两条路径产出同一 schema。
- 连带重命名：SQLite 字段、`Store::active_session_by_account_key`、
  `Workdir::account_keys()`、API 的 `key` body 字段与 `{key}` 路径变量、
  CLI `account add/show/remove/enable/disable` 的位置参数、前端 `AccountInfo.key`。

⚠️ 与 `Device.name` 命名不再一致 —— 有意为之：牺牲跨模型一致性，换取
「定位键」与「展示名」的字面区分度。
